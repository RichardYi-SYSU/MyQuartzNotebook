## 一、选择题

1. **D**

分析：在支持运行时地址重定位的系统中，逻辑地址到物理地址的转换由**内存管理单元（MMU）**这一硬件完成。编译器和链接器在编译/链接阶段工作，装入程序在加载阶段工作，它们都不能在运行时动态地进行地址转换。只有 MMU 能在每次 CPU 访存时实时将逻辑地址映射为物理地址。

2. **A**

分析：基址寄存器和界限寄存器的保护机制中，CPU 产生的逻辑地址 `x` 首先与界限寄存器（limit）比较，要求 `0 <= x < limit`（即逻辑地址不能超出进程的地址空间大小）。通过检查后，物理地址 = base + x。选项 B 混淆了逻辑地址和物理地址的关系。

3. **C**

分析：可变分区连续分配会产生大量**外部碎片**（进程之间的小空闲块）。分页存储将物理内存划分为等大的页框，进程的各个页可以分散存放在任意空闲页框中，从而**避免了外部碎片**，物理页框不必连续。但分页仍可能产生少量**内部碎片**（最后一页未填满的部分），因此 A 错误。

4. **B**

分析：TLB 是一种高速缓存，用于存放最近使用过的页表项。当 CPU 进行地址转换时，先查 TLB，若命中则无需访问内存中的页表，从而**加快地址转换速度**。TLB 与磁盘块索引、用户数据存储和页面置换算法无关。

5. **A**

分析：分段是面向程序员的逻辑划分方式，程序被划分为若干段，如代码段、数据段、栈段等，每个段有自己的名字和长度。各段长度可以不同（B 错误）；分段会产生**外部碎片**（C 错误）；分段地址由段号和段内偏移组成（D 错误）。

6. **A**

分析：缺页异常发生在 CPU 访问的页面**当前不在物理内存中**，且对应页表项的有效位标记为无效（invalid）时。此时操作系统需要将该页从磁盘调入内存。普通加法指令不一定触发缺页；TLB 命中说明页在内存中，不会缺页；读取已在内存中的页面也不会触发缺页。

7. **B**

分析：写时复制（Copy-on-Write, COW）的核心思想是：`fork()` 后父子进程**共享相同的物理页面**，这些页面被标记为只读。只有当其中某一方尝试**写入**某页面时，操作系统才为其复制一份该页面的副本。这样可以避免 `fork()` 时不必要的全量内存复制，提高效率。

8. **C**

分析：最优页面置换算法（OPT）的理论基础是：每次发生缺页时，选择**未来最长时间不会再被访问**的页面进行置换。这保证了最少的缺页次数。A 描述的是 FIFO；B 描述的是 LRU；D 描述的是随机置换。OPT 是理论最优算法，但由于需要预知未来的访问序列，在实际系统中无法实现，只能作为性能比较的基准。

9. **A**

分析：**Belady 异常**是指分配更多的页框反而导致更多缺页的反直觉现象。FIFO 算法不具有**栈性质**（stack property），因此可能出现 Belady 异常。而 LRU 和 Optimal 都是栈算法，具有栈性质，即增加页框数不会增加缺页次数，因此不会出现 Belady 异常。

10. **B**

分析：抖动（Thrashing）的典型表现是：系统中进程频繁发生缺页，操作系统把大量时间花在换页（页面调入/调出）上，而真正用于执行用户代码的 CPU 时间极少，**CPU 利用率反而下降**。抖动通常是由于多道程序度过高、每个进程分配的页框数不足导致的。

## 二、简答题

### 1. 请比较首次适应（First Fit）、最佳适应（Best Fit）和最差适应（Worst Fit）三种连续内存分配算法，并说明外部碎片与内存紧缩（Compaction）的关系。

**（1）三种算法比较**

| 特性       | 首次适应（First Fit）             | 最佳适应（Best Fit）              | 最差适应（Worst Fit）        |
| -------- | --------------------------- | --------------------------- | ---------------------- |
| **策略**   | 从头开始扫描，找到**第一个**足够大的空闲分区即分配 | 扫描所有空闲分区，选择**最小的**但能满足要求的分区 | 扫描所有空闲分区，选择**最大的**空闲分区 |
| **搜索速度** | 通常最快，找到即停止                  | 较慢，需要遍历所有空闲分区               | 较慢，需要遍历所有空闲分区          |
| **碎片特点** | 容易在低地址区域产生大量小碎片             | 会留下大量极小的难以利用的碎片             | 倾向于消除大的空闲块，中等碎片        |
| **利用率**  | 综合表现较好，实践中最常用               | 内存利用率较高，但小碎片多               | 大空闲区被迅速切割，后续大请求难以满足    |
|          |                             |                             |                        |

**（2）外部碎片与内存紧缩的关系**

**外部碎片**是指：空闲内存的总量足够满足某个请求，但这些空闲空间**不连续**，分散在已分配块之间，因此无法分配给需要连续空间的进程。

三种算法都会产生外部碎片，只是程度和形式不同。

**内存紧缩（Compaction）**是解决外部碎片的一种方法：将所有已分配的进程向内存的一端移动，从而将分散的小空闲块合并成一个大的连续空闲区。但紧缩有以下限制：

- **开销大**：需要移动大量内存中的数据，且在移动期间需暂停受影响的进程。
- **需要支持动态重定位**：只有在运行时使用基址寄存器进行地址映射的系统才能实现紧缩，静态绑定地址的系统无法做到。
- **不能频繁执行**：由于开销高，通常只在碎片严重时才触发。

### 2. 请解释分页系统中的页（page）、页框（frame）、页表（page table）和页表项（PTE）。一次普通内存访问在没有 TLB 和有 TLB 的情况下分别需要哪些步骤？

**（1）基本概念**

- **页（Page）**：将进程的**逻辑地址空间**划分成大小固定的块，每个块称为一页。典型大小为 4KB。
- **页框（Frame）**：将**物理内存**划分成与页相同大小的块，每个块称为一个页框（或帧）。
- **页表（Page Table）**：每个进程维护一张页表，记录逻辑页号到物理页框号的映射关系。页表存放在主存中。
- **页表项（PTE, Page Table Entry）**：页表中的每一条记录，包含页框号、有效位（valid/invalid bit）、保护位、修改位（dirty bit）、访问位（reference bit）等信息。

**（2）没有 TLB 的内存访问步骤**

1. CPU 产生逻辑地址，分解为**页号 p** 和**页内偏移 d**。
2. 用页号 p 作为索引，**第一次访问内存**：查找页表，得到页框号 f。
3. 检查有效位，若无效则触发缺页异常。
4. 若有效，将页框号 f 与偏移 d 拼接，得到物理地址。
5. **第二次访问内存**：用物理地址访问实际数据。

总共需要 **2 次内存访问**。

**（3）有 TLB 的内存访问步骤**

1. CPU 产生逻辑地址，分解为页号 p 和页内偏移 d。
2. 用页号 p **查找 TLB**（并行比较，速度很快）。
3. **若 TLB 命中**：直接从 TLB 获取页框号 f，拼接偏移得到物理地址，访问内存取数据。只需 **1 次内存访问**（加上 TLB 查询时间）。
4. **若 TLB 未命中**：需要访问内存中的页表获取页框号（1 次内存访问），同时将该页表项加载到 TLB 中，然后再访问实际数据（1 次内存访问），共 **2 次内存访问**。

### 3. 什么是请求分页？请描述从 CPU 访问一个不在内存中的页面开始，到该指令重新执行为止，操作系统处理缺页异常的大致流程。

**（1）请求分页（Demand Paging）**

请求分页是一种虚拟内存管理策略：进程启动时不将所有页面都调入内存，而是**只在需要时才将页面从磁盘调入内存**。也就是说，"按需调页"——只有当 CPU 实际访问某页面并发现该页不在内存中时，才触发缺页异常去加载该页面。

**（2）缺页异常处理流程**

1. **CPU 访问逻辑地址**，通过页表查找对应的页表项。
2. **检查有效位**：发现该页表项的有效位为无效（invalid），说明该页面当前不在物理内存中。
3. **触发缺页异常（Page Fault）**：CPU 产生陷阱（trap），将控制权转交操作系统。
4. **操作系统验证请求**：检查该地址是否合法（是否在进程的地址空间范围内）。若不合法，则终止进程。
5. **寻找空闲页框**：在物理内存中查找一个空闲的页框。
   - 若没有空闲页框，则需要执行**页面置换算法**（如 LRU、FIFO 等），选择一个牺牲页面。
   - 若被选中的牺牲页面被修改过（dirty bit = 1），需先将其写回磁盘。
6. **调入所需页面**：启动磁盘 I/O，将所需页面从磁盘（交换区或文件系统）读入到空闲页框中。
7. **更新页表**：将该页表项的页框号设为新分配的页框号，有效位设为有效（valid）。
8. **重新执行指令**：缺页异常处理完毕后，CPU 回到引起缺页的指令处，**重新执行**该指令。此时该页面已在内存中，访问将正常完成。

## 三、分析题

### 1. 分页系统地址转换与相关计算

页面大小 = 1KB = 1024 字节。

页表：

| 页号 | 有效位 | 页框号 |
|---|---|---|
| 0 | 1 | 5 |
| 1 | 1 | 9 |
| 2 | 0 | - |
| 3 | 1 | 2 |
| 4 | 1 | 11 |
| 5 | 0 | - |

#### （a）逻辑地址到物理地址的转换

**地址分解方法：**
- 页号 = 逻辑地址 ÷ 页面大小（取商）= 逻辑地址 ÷ 1024
- 页内偏移 = 逻辑地址 % 页面大小 = 逻辑地址 % 1024

---

**逻辑地址 100：**

- 页号 = 100 ÷ 1024 = **0**
- 页内偏移 = 100 % 1024 = **100**
- 页号 0 有效位 = 1，页框号 = **5**
- 物理地址 = 5 × 1024 + 100 = 5120 + 100 = **5220**

**逻辑地址 1350：**

- 页号 = 1350 ÷ 1024 = **1**
- 页内偏移 = 1350 % 1024 = **326**
- 页号 1 有效位 = 1，页框号 = **9**
- 物理地址 = 9 × 1024 + 326 = 9216 + 326 = **9542**

**逻辑地址 3220：**

- 页号 = 3220 ÷ 1024 = **3**（3 × 1024 = 3072，3220 - 3072 = 148）
- 页内偏移 = 3220 % 1024 = **148**
- 页号 3 有效位 = 1，页框号 = **2**
- 物理地址 = 2 × 1024 + 148 = 2048 + 148 = **2196**

**逻辑地址 5200：**

- 页号 = 5200 ÷ 1024 = **5**（5 × 1024 = 5120，5200 - 5120 = 80）
- 页内偏移 = 5200 % 1024 = **80**
- 页号 5 有效位 = **0** → **发生缺页异常（Page Fault）！**

**汇总：**

| 逻辑地址 | 页号 | 页内偏移 | 有效位 | 页框号 | 物理地址 |
|---|---|---|---|---|---|
| 100 | 0 | 100 | 1 | 5 | **5220** |
| 1350 | 1 | 326 | 1 | 9 | **9542** |
| 3220 | 3 | 148 | 1 | 2 | **2196** |
| 5200 | 5 | 80 | 0 | - | **缺页异常** |

#### （b）有效访问时间（EAT）计算

已知：
- 内存访问时间 = 100ns
- TLB 查询时间 = 10ns
- TLB 命中率 = 80%

**当 TLB 命中时**：TLB 查询 + 一次内存访问 = 10 + 100 = 110ns

**当 TLB 未命中时**：TLB 查询 + 访问内存中的页表 + 访问实际数据 = 10 + 100 + 100 = 210ns

**有效访问时间（EAT）：**

$$EAT = 0.8 \times 110 + 0.2 \times 210 = 88 + 42 = \textbf{130ns}$$

#### （c）保护位和修改位的用途

**保护位（Protection Bit）：**

- 用于控制页面的**访问权限**，如只读（read-only）、读写（read-write）、可执行（execute）等。
- 当进程试图进行违反保护位设定的操作时（如向只读页面写入数据），硬件会触发**保护异常**，操作系统进行相应处理（通常是终止进程或发送信号）。
- 这是实现内存保护的重要机制，防止进程篡改代码段或访问不允许的区域。

**修改位（Dirty Bit / Modified Bit）：**

- 用于标记某个页面自从调入内存以来是否被**修改过**。
- 当页面被写入时，硬件自动将修改位设为 1。
- 在**页面置换**时，如果修改位为 0，说明页面未被改动，不需要写回磁盘，可以直接丢弃，从而**减少磁盘 I/O 开销**。如果修改位为 1，则需要先将该页面写回磁盘后再置换。

#### （4）三者比较

| 算法          | 缺页次数   | 特点                                                               |
| ----------- | ------ | ---------------------------------------------------------------- |
| **FIFO**    | **10** | 实现最简单，只需维护一个队列。但性能最差，且可能出现 Belady 异常（增加页框数反而增加缺页次数）。             |
| **LRU**     | **8**  | 基于"最近的过去可以预测未来"的局部性原理，用过去的访问历史近似最优策略。性能接近 Optimal，是实践中常用算法的理论基础。 |
| **Optimal** | **7**  | 理论最优，缺页次数最少。但需要预知未来的访问序列，实际系统中无法实现，只能作为性能比较的下界（benchmark）。       |

本例中，Optimal（7 次）< LRU（8 次）< FIFO（10 次），与理论预期一致。
