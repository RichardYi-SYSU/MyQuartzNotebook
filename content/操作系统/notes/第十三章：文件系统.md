
# 文件操作

- Create创建
- Write写入写指针当前位置
- Read读取当前指针位置的内容
- Reposition文件内重新定位，改变指针的位置，控制从文件的哪个位置开始读或写
- Delete删除文件名和文件本身
- Truncate截断文件，保留文件但清空或缩短文件内容
- open在磁盘中查找该文件，然后把它放到内存中
- close把内存中更新过的文件信息写回磁盘目录结构

|**操作**|**文件名是否保留**|**文件内容**|
|---|---|---|
|Delete|不保留|文件被删除|
|Truncate|保留|内容被清空或缩短|

## 管理文件所需的一些数据

- Open-file table：进程打开表，通常有：

```
文件位置
文件大小
访问模式
当前读写位置
引用计数
磁盘块信息
```
 
- File pointer：文件指针，指向最后读/写的位置，记录下一次读/写从文件的哪里开始，每个打开该文件的进程，通常都有自己的读写位置。两个进程打开同一个文件时，它们的文件指针可能不同
- File-open count：用于计数当前已打开的文件，判断什么时候可以真正清理内存中的打开文件信息
- Disk location of the file：文件在磁盘上的位置，记录文件数据实际存放在哪些磁盘块中，方便快速访问
- Access rights：访问权限，记录当前进程以什么权限打开了这个文件

# 文件锁

> 多个进程同时访问同一个文件时，如何避免读写冲突？

共享锁：

- 多个进程可同时持有共享锁
- 适用于只读文件

互斥（独占）锁：

- 同一时刻只能有一个进程持有独占锁
- 适合于写文件、修改文件、截断文件的场景
- 写 + 读：不允许、写 + 写：不允许

强制性锁：

- OS强制执行锁规则
- 如果一个文件已被某个进程加了互斥锁，那么其他进程即使不主动检查锁直接读写，也会被OS拒绝

建议性锁：

- 锁只是个协作约定
- 进程需主动检查

# 文件结构

> 操作系统或应用程序如何理解一个文件内部的数据组织形式

无结构文件：

- 文件只是一个连续的字节序列，操作系统不关心里面是什么，字节流

简单记录结构：

- 按行组织
	- 常见于文本文件、日志文件、CSV文件
- 定长记录
	- 每条记录长度固定
	- 易于随机访问
- 变长记录
	- 每条记录长度不固定
	- 节省空间、随机访问麻烦

复杂结构：

- 格式化文档
	-  比如.doc .pdf .html 
	- 除普通文本外还包含其他信息
- 可重定位装入文件
	- 与程序运行有关的文件
	- 其中不光有机器指令，还有代码段、数据段等
	- 可重定位：程序装入内存时，不一定总是放在固定地址。文件里需要记录哪些地址在装入时要被修改
- 只要有合适的标记、分隔符、头部信息、控制字符，字节流也可以表达复杂结构。

# 文件访问顺序

顺序访问

- 从文件头开始，按顺序一个接一个地读或写
- 类似磁带、播放视频、读日志
- 随机查找效率低

直接访问

- 也叫随机访问
- 可以直接跳到文件中某个位置读写
- 可以快速定位
- 适合数据库、索引文件、二进制文件
- 依赖 seek 操作
- 对磁盘、SSD 很常见

其他访问顺序（常见索引访问）

- 类似查字典目录

比如一个学生文件：

```text
学号  姓名  成绩
1001  张三  90
1002  李四  85
1003  王五  92
```

如果文件很大，直接从头顺序查找 `1003` 很慢。

于是建立一个索引：

```text
1001 → 文件位置 0
1002 → 文件位置 100
1003 → 文件位置 200
```

查找学号 `1003` 时：

```text
先查索引，得到位置 200
再直接访问文件位置 200
```

所以索引访问本质是：

```text
索引查找 + 直接访问
```


# 磁盘结构

- 磁盘或分区可以在没有文件系统的情况下直接使用，也可以用文件系统进行格式化
- 包含文件系统的实体称为卷
- 目录directory是一个管理表，用来记录这一分区/卷中有哪些文件，以及这些文件在哪里

```
partition A
├── directory：记录 A 分区有哪些文件
└── files：A 分区中文件的真实内容

partition B
├── directory：记录 B 分区有哪些文件
└── files：B 分区中文件的真实内容
```


# 目录结构

## 单极目录

- 有命名问题
- 无法分组管理

## 两级目录结构

- 主文件目录其下有用户文件目录
- 每个用户有自己目录，所以不同用户可以有同名文件
- 需要路径名来确定文件

## 树形目录

- 一个文件或目录只有一个父目录
- 不允许一个文件出现在两个不同目录下

## 无环图目录

- 同一个文件可以有两个不同的名字或路径
- 多个用户可以共享同一个文件，不用复制多份，修改一次，所有路径看到内容都变
- 悬空指针，其中一个目录删除了这个文件，但另一个目录还有一个指向它的链接
	- 使用反向指针解决，让文件记录有哪些目录项指向我
	- 菊花链，把所有反向指针串成一条链
	- 引用计数，给真实文件维护一个计数，记录有多少目录项指向这个文件
- Link，指向已有文件的另一个名字，给已有文件增加一个新名字或路径

### 硬链接

> 多个目录项直接指向同一个文件对象

- 删除一个名字，文件不一定消失
- 只有引用计数变成0，文件才会被删除
- 不同文件，指向同一个inode
- 一般不给目录创建硬链接，因为可能会出现环路

> inode 文件的唯一id
### 软链接

软链接更像是一个特殊文件，里面保存目标路径：

```text
B/list → "A/list"
```

访问 `B/list` 时，系统再去找 `A/list`。

如果 `A/list` 被删除，那么：

```text
B/list → A/list
```

就找不到目标了，这时软链接就会变成 **悬空链接 dangling link**。

所以软链接更容易出现 dangling pointer 问题。
