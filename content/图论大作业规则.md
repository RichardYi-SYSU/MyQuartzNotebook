
一、校验逻辑

|   |
|---|
|1. 航班是否存在于原始数据中<br><br>2. 航班 ID / 航班号是否能和原始数据精确匹配<br><br>3. 相邻航班机场是否能衔接<br><br>4. 时间顺序是否合理<br><br>5. 是否满足最小过站时间<br><br>6. 是否要求同机型<br><br>7. 是否重复使用航班|

二、关于重复航班环

（1）按现在这个评分脚本的逻辑，**不会把一个大航班环自动拆成几个小航班环再分别计分。比如**

A → B → A → C → A

这个序列里面确实可以看成包含两个小环：

A → B → A

A → C → A

但是最终会被作为一整行提交的，系统只会判断一个大航班环，长度为这一整行的航班段数量。也就是说，同一行只算一次，不会大环、小环重复得分。

（2）还有一种情况，如果他既提交大环，又把大环里面的小环也单独提交，例如：

第1行：A → B → A → C → A

第2行：A → B → A

第3行：A → C → A

这样的话就有重复的航班环，系统只会给大环的分，但是如果只提交2行和3行的话，就会给这两行的分数。

三、非法数据

第一类格式错误

|   |
|---|
|日期为空或无法解析<br><br>机型为空<br><br>链类型不是“航班串”或“航班环”<br><br>是否闭环不是“是/否”<br><br>航班号序列为空<br><br>航班ID序列为空<br><br>航班数量小于 2<br><br>航班号数量和航班ID数量不一致<br><br>填写的航班数和实际序列长度不一致<br><br>起点机场为空<br><br>终点机场为空<br><br>机场路径为空|

第二类数据错误

（1）系统会拿学生提交的航班去源数据里查。如果学生写了一个源数据里不存在的航班，例如：

|   |
|---|
|FLIGHT_ID = 999999<br><br>FLIGHT_NO = CZ9999<br><br>日期=2026-4-04|

（2）航班串或航班环要求相邻航班机场连续，但是提交的数据里面有不连续的机场，比如：

广州 → 北京

上海 → 成都

那中间就断了，因为不一致，这一行就是非法行。

（3）时间错误

系统会检查后一段航班的起飞时间**是否晚于**上一段航班的到达时间，并且是否满足最小过站时间。现在最小过站时间默认是0

（4）机型不一致

同一行航班环/航班串里的所有航班必须是同一机型。比如一行里面：

A320 → A320 → B737

那就非法。系统会进行删去，不会计分。

**特别注意：提交文件命名一定要是自己的学号命名，比如24344542.xlsx。要分析的数据有三个表，就是要分别去进行优化分析，然后再汇总到一个表里面提交即可，其实就是这三个每个表都是独立了，不能开始就放在一起分析。**
